# 제품 광고와 앱 시연

## 자료와 메시지

공식 로고, 실제 UI 캡처나 녹화, 제품 사진과 모델, 브랜드 색과 글꼴을 지정된 자료에서 찾는다. 고객 정보가 보이는 화면은 사용 전에 가린다. 캡처는 최대 확대 배율에 맞는 해상도로 확보한다. 확인되지 않은 기능과 수치를 광고의 사실로 쓰지 않는다. 없는 UI나 모델은 콘셉트임을 표시한다.

대상, 한 가지 핵심 효용, 그 효용을 보여 주는 동작, 마지막 행동 유도 문구를 정한다. 새 짧은 영상에서 규격이 없으면 15초, 1920×1080, 30 fps를 초안으로 삼고, 숏폼이면 1080×1920으로 구성한다. 기존 프로젝트와 사용자 지정이 우선이다.

## 여러 장면을 만드는 경우

대체로 문제나 제품 제시, 실제 기능의 증명, 결과와 행동 유도를 연결한다. [스토리보드 서식](../assets/storyboard-template.md)에 필요한 행만 쓴다. 프레임 범위는 `[시작, 끝)`이며 전체 구간에 빈틈과 중복이 없어야 한다. 겹치는 전환은 하나의 연속 구간으로 계획한다.

“버튼이 넓어져 다음 결과 카드가 된다”처럼 첫 자세, 마지막 자세, 연결 물체와 시선을 정한다. 문구를 읽는 시간과 실제 조작의 인과관계를 우선한다. 커서는 클릭 위치까지 움직이고 클릭 직후 화면이 반응하게 한다. 마지막 행동 유도 화면 전에 불필요한 커서를 치운다.

## 엔진과 확인

2D는 [2D 모션](motion.md), 3D가 필요한 장면만 [Blender](blender.md)를 읽는다. 이미 가진 엔진으로 충분하면 바꾸지 않는다.

제품 시연은 화면과 설명 시간을 먼저 안정시키고 소리를 맞춘다. 음악 박자가 중심인 요청이면 [쇼릴](showreel.md)의 음악 우선 절차를 사용한다. 소리를 요청하지 않은 단독 시연에 내레이션을 강제하지 않는다.

실제 제품과 화면, 로고 형태, 글자 잘림, 전환 경계, 마지막 화면을 확인한다. 세로 영상은 게시 플랫폼의 현재 공식 안전 영역 안내나 템플릿으로 가림 영역을 피한다. 출력 형식에 필요한 검증만 수행한다.
